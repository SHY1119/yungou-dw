# 第四周周记

- 团队：云购数智队　成员：孙浩瑜　时间：2026-11-16 ~ 2026-11-20
- 本周主题：可视化与多服务部署 · Superset 仪表板 + ECharts 大屏 + Streamlit 问答 · 查询优化与压测

## 一、本周完成的工作

前三周把数仓做"可信、可分析"之后，本周的任务是让数据"被看见"：一个 BI 仪表板、一块大屏、一个智能问答入口，全部容器化一键部署。

**三套可视化界面全部落地并实测。** Superset 仪表板接入 Hive、ClickHouse、MySQL 三个数据源，建了 9 个数据集、8 个图表（销售趋势折线、品类柱状、区域分布地图、支付饼图、门店 Top10 表、用户分层、时段×品类热力图、ClickHouse 加速对照）加两个原生筛选器，每个图表都确认渲染出真实数据。ECharts 大屏按 1920×1080 设计、scale 自适应，7 个图表 + 6 张 KPI 卡片，Flask 后端提供 8 个 JSON 接口，数据取自 Hive ADS 层导出。Streamlit 问答接上周的 NL2SQL 引擎，实测闭环："广东省上月销售额是多少？"→ 生成 SQL → Hive 执行 → 返回 184,363.16 元，耗时 6.3 秒，与第 3 周验证值一致。

**Docker Compose 从 3 容器扩展到 7 容器。** 新增 ClickHouse（ADS 加速层）、Superset、Streamlit 应用三个服务，用 healthcheck 依赖链控制启动顺序（mysql → metastore → hiveserver2 → superset/app），敏感信息统一走根目录 `.env` 注入，`.gitignore` / `.dockerignore` 双重排除密钥文件。`docker compose up -d` 一条命令拉起全栈。

**查询优化与压测。** 写了三组优化对比 SQL（分区裁剪、加盐两阶段聚合抗倾斜、ORC 预聚合），压测脚本跑 3 组查询 × 4 并发 × 5 轮：预聚合平均 4.62 秒 / 分区裁剪 5.69 秒 / 全表扫描 6.08 秒，失败 0，P95 与均值同步记录。

## 二、遇到的问题与解决

**1. 容器里访问不了宿主机 Docker——架构级约束逼出了双执行模式。** 容器化 Streamlit 后，NL2SQL 原来的 `docker exec` 调 beeline 的方式直接失效（容器内没有宿主机 Docker daemon）。解决：给 nl2sql.py 增加 `HIVE_URI` 环境变量触发的 pyhive 直连模式，经 Thrift 协议直连 hiveserver2；宿主机默认行为不变。依赖上又踩一坑：`sasl` 包的 C 扩展在容器里编译失败，换 `pure-sasl` 纯 Python 实现才通。

**2. Metastore 崩溃循环，根因是一个"自动创建的空目录"。** 从仓库目录重建容器后 metastore 反复重启，日志里是 `ClassNotFoundException: com.mysql.cj.jdbc.Driver`。排查发现 compose 挂载的 `./lib/mysql-connector-j-8.0.33.jar` 在仓库目录下不存在——Docker 对不存在的 bind mount 源会自动创建一个同名**目录**，掩盖了"文件缺失"这个真相。把真正的 jar 拷入后恢复。教训：bind mount 源缺失是静默失败，部署检查清单里必须有一项"确认 jar 在位"。

**3. Superset 内置中国地图不认中文省名。** 区域地图图表报数据全空，翻源码才发现内置地图是 GADM 数据，匹配键是 ISO 码（CN-GD）而非省名。先用 CASE 映射英文省名不生效，再改成 ISO 码才着色成功。同一类问题还有 country_map 图表的参数键名——报错只说 "Must specify a country"，最后是让 AI 直接读 Superset 源码确认参数叫 `select_country`、`entity`，一次改对。地图数据用国标行政区划 GeoJSON（含南海诸岛），不用任何境外瓦片源。

**4. 8 个图表并发把 Tez 会话踩塌了。** 单查每个图表的 SQL 全部正常，仪表板上却有一半卡片偶发 `Invalid input path`。单查能过、并发必挂，定位是多 Tez 会话并发访问同一分区的资源竞争。先试了加会话数（4 个），失败依旧；改成会话串行（sessions=1）后稳定，代价是首屏加载约 40 秒。同时把两个重查询（支付方式、时段×品类热力）物化成 ORC 小表，图表查小表，把串行的代价压到最低。

**5. 小问题一串：** ClickHouse 空密码的认证行为和预期不符，设显式密码解决；Superset 仪表板 position_json 布局层级不完整导致前端不渲染，按 v1 规范重建；pip 和 python 不是同一个环境，装了包却 import 不到，统一改用 `python -m pip`。

## 三、学习收获

**1. "单查询能跑通"和"系统能演示"之间隔着一层工程。** 前三周验证的都是单条 SQL、单个脚本；本周第一次把多个组件放在同一个仪表板里并发访问同一个 Hive。问题全在交集处：并发会话竞争、依赖启动顺序、容器网络互通。做集成，就是做这些交集。

**2. 可视化有它自己的数据工程。** 大屏的 8 组接口数据看起来只是"从 Hive 查出来存 JSON"，实际坑不少：TSV 输出的 double 是科学计数法字符串、表头带表名前缀、省名要和 GeoJSON 匹配。前端图表"不显示"时，十有八九是数据侧的口径或格式问题，不是图表库的问题。

**3. 地图是可视化里最需要合规意识的图。** 中国省级地图必须用国标行政区划数据、必须包含南海诸岛和台湾省、不能用境外瓦片源。这次从选 DataV GeoAtlas 到校验省名匹配，每一步都按合规守卫的要求留痕。

**4. 让 AI 读源码比让 AI 猜参数高效得多。** Superset 地图参数报错信息含糊，盲试三轮都没对；改成把报错抛给 AI 并让它去容器里 grep 源码，一次定位参数键名。AI 协同的正确姿势是给它原始材料（源码、日志、报错全文），而不是转述。

## 四、不足与改进

- 大屏数据是静态 JSON 快照，不是实时接口；真实场景应接 ClickHouse/Superset 的查询 API，或定时刷新导出。
- Superset 仪表板首屏因 Tez 串行要等约 40 秒，演示体验一般；后续可考虑关键图表直接走 ClickHouse 加速层。
- 压测规模小（4 并发 × 5 轮），且只压了 Hive，没有对 ClickHouse 做对照压测来量化加速收益。
- Streamlit 问答目前每次提问都现生成 SQL，没有缓存常用问题的结果。
