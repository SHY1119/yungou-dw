# 需求文档

项目：云购生活新零售企业——企业级数据仓库与经营分析可视化系统
团队：云购数智队　成员：孙浩瑜　版本：v1.0（2026-11-17）

## 一、业务背景

云购生活是一家连锁新零售企业，线下门店覆盖全国 15 个省（市），在营门店 60 家，注册会员 1,000 名，经营生鲜、粮油、日化等 8 大品类 600 种商品。2024-06 至 2025-06 期间累计产生订单 1.56 万笔、订单明细 3.75 万条、用户行为流水 6 万条。

企业在数字化经营中面临三个核心痛点：

1. **数据孤岛**：订单、会员、商品、门店数据分散在不同业务库，缺乏统一的全局视图；
2. **口径混乱**：GMV、客单价、复购率等经营指标各部门统计口径不一致，决策依据不可靠；
3. **分析滞后**：经营分析依赖人工导出 Excel，无法支撑日常运营的时效性要求。

为此立项建设企业级数据仓库与经营分析可视化系统，目标是将分散数据整合为标准化四层数仓，沉淀统一指标体系，并通过 AI 与可视化能力让经营数据"可查、可比、可预测、可对话"。

## 二、需求分析

### 2.1 功能需求

| 编号 | 需求 | 说明 | 承载模块 |
|---|---|---|---|
| FR-01 | 数据接入 | 6 类业务数据全量导入 ODS 层，行数与数据字典逐表一致 | sql/ods |
| FR-02 | 数据清洗 | 缺失值、重复值、枚举异常、格式异常、离群值五类脏数据处理，产出修复率报告 | sql/clean |
| FR-03 | 维度建模 | DWD 星型模型：1 事实订单表 + 1 明细事实表 + 5 维表，按日分区 | sql/dwd |
| FR-04 | 汇总服务 | DWS 按日/门店/会员等维度预汇总，支撑 ADS 快速取数 | sql/dws |
| FR-05 | 指标看板 | GMV、AOV、ARPU、履约率、复购率、优惠率 6 项核心 KPI 及品类/区域/时段多维分析 | sql/ads |
| FR-06 | 销售预测 | 未来 7 天 GMV 时间序列预测，MAPE 优于 15% | scripts/forecast_gmv.py |
| FR-07 | 自然语言查询 | 中文提问 → SQL → 结果表格/图表自动渲染，只读安全拦截 | scripts/nl2sql + streamlit_app |
| FR-08 | AI 洞察 | 基于 ADS 结果自动生成经营分析摘要，AI 产出与人工核验双版本留存 | scripts/insight.py |
| FR-09 | 可视化大屏 | 1920×1080 经营大屏：趋势/品类/区域地图/热力/TopN/KPI 卡片 | vis/bigscreen |
| FR-10 | BI 仪表板 | Superset 仪表板 8 图表 + 原生筛选器，含 ClickHouse 加速对照 | Superset |
| FR-11 | 一键部署 | docker compose 一键拉起全部 6 服务，密钥经 .env 注入 | docker-compose.yml |

## 三、指标体系定义

| 指标 | 定义 | 口径边界 |
|---|---|---|
| GMV | SUM(dwd_order.pay_amount) | 实付金额口径（含优惠后）；不含未支付订单 |
| AOV | GMV / 订单数 | 按 dwd_order 去重后订单粒度 |
| ARPU | GMV / 活跃用户数 | 活跃用户 = 期间内有成功订单的会员 |
| 复购率 | 期间下单 ≥ 2 次会员数 / 下单会员数 | 按自然月窗口计算 |
| 履约率 | 已完成订单数 / 总订单数 | 以订单状态枚举为准 |
| 优惠率 | 1 - 实付合计 / 挂牌应付合计 | 与明细金额口径区分，差异已在指标文档标注 |
| 品类销售额 | SUM(item_amount) | 挂牌价×数量口径，用于品类结构占比 |
| 日均 GMV | 期间 GMV / 366 天 | 与 ads_sales_daily 逐日汇总可复算 |

指标口径完整定义见《指标定义文档》；指标与物理表映射及勾稽验证见《端到端联调核对清单》。

## 四、用户与场景

| 角色 | 场景 | 触达方式 |
|---|---|---|
| 经营管理层 | 每日经营例会查看 GMV/客单/区域表现 | ECharts 大屏 + Superset 仪表板 |
| 运营分析师 | 品类结构、时段热力、会员分层下钻 | Superset 筛选器 + ADS SQL |
| 数据工程师 | 指标口径追溯、数据质量监控 | 五大文档 + 联调核对清单 |
| 一线业务人员 | 自然语言直接提问经营数据 | Streamlit NL2SQL 问答 |

## 五、验收标准

1. 全流程（CSV → ODS → DWD → DWS → ADS → AI/可视化）端到端可复现运行；
2. 各层行数与指标值逐层勾稽一致（见联调核对清单，全部通过）；
3. 清洗修复率 ≥ 95% 且五类脏数据均有处理记录；
4. 预测 MAPE ≤ 15%（实测 13.89%）；
5. NL2SQL 测试通过且写操作请求 100% 拦截；
6. `docker compose up -d` 一键启动全部服务并 healthy。
