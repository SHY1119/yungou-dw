## 四、问题与解决

- **遇到的问题 1**：XGBoost 时间序列预测训练集误差趋零、测试集 MAPE 反超朴素基线。
- AI 是否有效解决：部分有效。AI 给出了对照组，但初稿未主动报告过拟合信号。
- 最终如何解决：人工审阅评估表发现异常，判定弃用 XGBoost，改用线性回归（MAPE 13.89%），并把"时间序列禁止随机切分、模型须对照朴素基线"写入报告方法论。
- **遇到的问题 2**：Prompt 模板 `{枚举}` 与 `str.format` 占位符语法冲突，NL2SQL 首跑即 KeyError。
- AI 是否有效解决：有效。AI 定位到花括号被格式化引擎解析的根因，改用全角括号。
- 最终如何解决：模板字符调整后 6/6 测试通过；此坑记入环境笔记防复发。
- **遇到的问题 3**：洞察脚本把 tsv 表头行当作数据行，AI 归因依据错位。
- AI 是否有效解决：部分有效。AI 生成的脚本存在该 bug，但经人工指出后快速修复。
- 最终如何解决：修复解析逻辑并重跑；同时确立"AI 洞察必须产出人工核验版"的流程，原始输出与核验版双留存。
- **遇到的问题 4**：GitHub 网络不稳，PR 分支推送多次超时。
- AI 是否有效解决：有效。AI 给出 SSH/HTTPS 交替推送与重试策略。
- 最终如何解决：重试后推送成功，PR #2 合并，tag v1.0-week3 推送完成。

## 五、反思与总结

- **AI 协同带来的价值**：本周工程密度最高（SQL 建模 + Python 预测 + LLM 接口 + Git 工作流），AI 使全链路从设计到可演示耗时控制在一天内；NL2SQL 的 Prompt 三防线设计体现了 AI 不只写代码、还能参与安全设计。
- **AI 的局限与风险**：① 模型评估盲区——AI 不会主动宣告自己生成的模型过拟合，评估结论必须人工复核；② 输出质量依赖输入质量——洞察脚本表头 bug 说明"给 AI 的数据有问题，AI 的结论一定有问题"；③ 安全边界需要对抗性验证——Prompt 防线设计合理不代表有效，写请求注入实测才可确认；④ AI 生成内容的"两版本留存"（原始 vs 核验）应作为标准流程，避免直接采信。
- **本次协作中我的能力提升**：① 掌握了时间序列建模的正确姿势（时间序切分、朴素基线对照、适用边界声明）；② 理解了 LLM 应用的工程闭环——Prompt 设计、密钥管理、执行封装、结果校验缺一不可；③ 完整走过一次 Fork → PR → Review → 冲突解决 → tag 的协作流程，理解了"留痕"对团队协作的意义。
- **对 AI 协同的改进建议**：① 模型评估类产出应强制附带"与朴素基线对照"一栏，防止过拟合被静默放过；② 涉及外部 API 的代码应默认生成 `.env` 读取逻辑而非硬编码，从源头杜绝密钥泄露；③ AI 洞察类产出建议 AI 在输出时同步标注每条结论的数据出处，降低人工核验成本。
